<objective>
Put every browser-facing byte behind one Caddy origin, give the AXIAM console its own host so its cookies cannot collide with the portals', serve a static front door that proves the TLS chain works in a real browser, and bring PostgreSQL into the same stack with its own root-signed certificate.

Purpose: PLAT-06 is what makes the demo narratable — one URL, no CORS, no port juggling. It is also where the two most expensive mistakes hide: a matcher written in the wrong order silently swallows Phase 2's and Phase 3's own API routes, and a shared host silently destroys one of two logged-in sessions.

Output: `deploy/caddy/Caddyfile`, the landing page, the PostgreSQL service, and `just edge-verify`.

**Reversibility:** all `reversible`. The route map (D-30) and landing page (D-31) can be rewritten at any time; the console-on-its-own-host choice is the only one with a downstream cost, and it is a Caddyfile edit plus an mDNS alias, not a data migration.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN browser → `caddy:443` | The only browser-facing entry point. Untrusted requests, untrusted headers. |
| `caddy` → `axiam-server:8090` / `device-twin:8443` | Internal hops. Both must be TLS-verified against the offline root with an explicit server name. |
| `{DOMO_HOST}` ↔ `axiam.{DOMO_HOST}` | A cookie boundary, not merely a routing one. AXIAM's session cookies are host-scoped. |
| `postgres` | Inside the compose network only; never published. |
